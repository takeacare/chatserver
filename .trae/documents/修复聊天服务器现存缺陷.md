# 修复聊天服务器现存缺陷

## 一、摘要

对 `/home/lyq/桌面/project/chatserver` 做一次正确性与健壮性修复，覆盖四类问题：

1. **协议无分帧**：客户端/服务端都假设一次收发等于一条完整 JSON，存在 TCP 粘包/拆包隐患。
2. **SQL 不安全**：所有 SQL 用 `sprintf` 拼接，存在注入、引号破坏、`char[1024]` 截断/溢出。
3. **数据库连接无池化**：每次 Model 操作新建一条 MySQL 连接，且 `UserModel::query` 存在结果集未释放。
4. **Redis 与客户端细节缺陷**：`unsubscribe(-1)`、hiredis 上下文多线程竞争、客户端 `recv` 固定 1024 缓冲区越界与 `strlen+1` 发送。

用户已确认：**全部修复（含连接池）**，协议采用 **4 字节网络序长度前缀分帧**。

## 三、修改方案

### 1. 协议分帧（公共层）

**文件：`include/public.hpp`（修改）**

新增内联工具，客户端与服务端共用：

```cpp
#include <cstdint>
#include <cstring>
#include <string>
#include <arpa/inet.h>

static const size_t MAX_MSG_LEN = 4 * 1024 * 1024; // 单帧上限 4MB

// 给 JSON 负载加 4 字节网络序长度头
inline std::string encodeMessage(const std::string &payload)
{
    uint32_t len = htonl(static_cast<uint32_t>(payload.size()));
    std::string frame(reinterpret_cast<const char *>(&len), 4);
    frame.append(payload);
    return frame;
}
```

约定：**线上字节流 = 4 字节 big-endian 长度 L + L 字节 JSON**。长度非法（`L == 0` 或 `L > MAX_MSG_LEN`）视为协议错误，关闭连接。`public.hpp` 已有 include guard，供客户端与业务层包含。

### 2. 服务端接收分帧

**文件：`src/server/chatserver.cpp`（修改 `onMessage`）**

- 循环处理 muduo `Buffer`：当 `readableBytes() >= 4` 时用 `buffer->peek()` 读长度头，`ntohl` 得到 `len`；校验 `0 < len <= MAX_MSG_LEN`，否则 `LOG_ERROR` 并 `conn->shutdown()` 后返回。
- 若 `readableBytes() < 4 + len`，直接 `return`，剩余字节留在 muduo Buffer 中等下次回调（无需额外成员变量）。
- 满足整帧后 `retrieve(4 + len)` 取出帧，`json::parse(payload)`；解析异常用 `try/catch` 包住并记日志，不崩溃。
- 保留“`msgid` → `getHandler` → 调用”的分发逻辑；把原先的 `cout << buf` 改为打印 payload。
- 一次回调内可能有多个完整帧，需 `while` 循环全部处理。

### 3. 业务层发送统一加帧

**文件：`include/server/chatservice.hpp`（修改）**

新增私有方法声明：

```cpp
void sendJson(const TcpConnectionPtr &conn, const json &js); // 帧化后发送
```

**文件：`src/server/chatservice.cpp`（修改）**

- 实现 `sendJson`：`conn->send(encodeMessage(js.dump()))`。
- 把 `login`、`reg` 中所有 `conn->send(response.dump())`、`oneChat`/`groupChat` 的 `it->second->send(js.dump())` 全部改为 `sendJson(...)` 或 `conn->send(encodeMessage(js.dump()))`。
- [clientCloseException](file:///home/lyq/桌面/project/chatserver/src/server/chatservice.cpp#L220-L247)：把 `_redis.unsubscribe(user.getId())` 移入 `if (user.getId() != -1)` 分支内。
- Redis 路径保持**纯 JSON**：`publish` 仍发 `js.dump()`，`handleRedisSubscribeMessage` 收到后改为 `it->second->send(encodeMessage(msg))`；离线消息仍以纯 JSON 存库（登录响应里的 `offlinemsg` 是 JSON 字符串数组，不能塞二进制帧）。

### 4. 客户端分帧与发送封装

**文件：`src/client/main.cpp`（修改）**

- 新增本地辅助函数：

```cpp
static bool sendAll(int fd, const std::string &data); // 循环 send 直到写完，处理 EINTR/短写
static bool sendFrame(int fd, const std::string &json); // sendAll(fd, encodeMessage(json))
```

- 7 处 `send(clientfd, ..., strlen+1, 0)` 改为 `sendFrame(clientfd, request)`。
- `readTaskHandler` 重写为流式解帧：
  - `char chunk[4096]` 只作为 `recv` 临时缓冲，追加到 `std::string recvBuf`；
  - `while (recvBuf.size() >= 4)`：解出长度，校验上限；不足 `4+len` 则 `break` 等下次；
  - 取出 payload → `json::parse`（`try/catch`）→ 按 `msgid` 走原有分发（私聊/群聊/登录/注册）；
  - `recv` 返回 `0` 打印“服务器关闭连接”后退出；返回 `-1` 区分 `EINTR`（继续）与其他错误（打印并退出）。
  - 原有 `sem_post` 同步逻辑保持不变。

### 5. MySQL 连接池

**新增文件：`include/server/db/connectionpool.h`、`src/server/db/connectionpool.cpp`**

- 单例 `ConnectionPool`：

```cpp
class ConnectionPool {
public:
    static ConnectionPool &instance();
    void init(const std::string &host, int port, const std::string &user,
              const std::string &pwd, const std::string &db, size_t size);
    MYSQL *acquire();          // 队列空且未达上限则新建，否则条件变量等待
    void release(MYSQL *conn); // mysql_ping 失败则销毁重建，成功则归还
    ~ConnectionPool();         // 关闭所有连接
private:
    MYSQL *createConn();
    std::queue<MYSQL *> _idle;
    std::mutex _mtx;
    std::condition_variable _cv;
    size_t _maxSize;
    size_t _created;
    ...配置字段
};
```

- 默认参数：`127.0.0.1:3306`、`root/123456`、库 `chat`、池大小 `8`（4 个 muduo worker + Redis 回调线程，留余量）。
- 建连时执行 `mysql_query(conn, "set names utf8mb4")`。
- 服务器启动时初始化：在 `src/server/main.cpp` 的 `EventLoop loop;` 之前调用 `ConnectionPool::instance().init(...)`；参数硬编码沿用原 `db.cpp` 中的默认值（配置化不在本次范围）。

**文件：`include/server/db/db.h` / `src/server/db/db.cpp`（修改）**

- `MySQL` 改为**池连接 RAII 句柄**：
  - 构造函数：`_conn = ConnectionPool::instance().acquire();`
  - 析构函数：`ConnectionPool::instance().release(_conn);`（不再 `mysql_close`）。
  - `connect()`：改为返回 `_conn != nullptr`（保留签名，减少 Model 改动）。
  - `update/query`：参数改 `const string &`；连接为空时返回失败。
  - 新增 `string escape(const string &raw)`：用当前 `_conn` 调 `mysql_real_escape_string`，返回转义结果。
- 删除 `db.cpp` 顶部四个静态配置与 `set names gbk` 语句（字符集设置移入池的建连逻辑）。

### 6. Model 层安全化

四个 Model 统一做法：**用 `std::string` 拼 SQL + 数值用 `std::to_string` + 字符串用 `mysql.escape(...)`**，删除所有 `char sql[1024]` 与 `sprintf`。

- **`src/server/model/usermodel.cpp`**
  - `insert`：`"insert into user(name,password,state) values('" + escape(name) + "','" + escape(pwd) + "','" + escape(state) + "')"`。
  - `query`：`"select * from user where id=" + to_string(id)`；**所有分支都调用 `mysql_free_result(res)`**（含 `row == nullptr`）。
  - `updateState` / `resetState`：同规则改写。
- **`src/server/model/offlinemessagemodel.cpp`**
  - `insert`：`msg` 必须 `escape`；`remove/query` 用 `to_string`。
- **`src/server/model/friendmoel.cpp`**：仅数值拼接，改 `std::string`，逻辑不变。
- **`src/server/model/groupmodel.cpp`**
  - `createGroup` 的 `groupname/groupdesc`、`addGroup` 的 `role` 必须 `escape`。
  - `queryGroups`：把两次查询放在 `if (!mysql.connect()) return {};` 之后，避免未连接就 `query`；确保每条结果集都释放。
  - `queryGroupUsers` 改 `std::string`。

### 7. Redis 线程安全与错误处理

**文件：`include/server/redis/redis.hpp`（修改）**

- 新增 `std::mutex _pubMutex;` 与 `std::mutex _subMutex;`（包含 `<mutex>`）。

**文件：`src/server/redis/redis.cpp`（修改）**

- `connect()`：创建两个上下文后，除判空外同时检查 `ctx->err != 0`，失败时 `redisFree` 并返回 `false`。
- `publish()`：`lock_guard<mutex>` 保护 `_publish_context` 的 `redisCommand`。
- `subscribe()/unsubscribe()`：`lock_guard<mutex>` 保护 `_subcribe_context` 上的 `redisAppendCommand + redisBufferWrite`。
- `observer_channel_message()` 的 `_notify_message_handler` 调用保持不变（不再加锁，避免与 sub 锁互相阻塞）。
- 说明：`redisGetReply` 独立线程阻塞读取，与加锁后的 append 写操作在语义上互斥；这是本项目中可接受的修复边界，不引入连接重建。

## 四、假设与决策

- **协议整体升级**：客户端与服务端必须同时重新编译，旧版本二进制不兼容；`test/` 下的示例程序不参与协议，不改动。
- **离线消息与 Redis 载荷保持纯 JSON**：只有 TCP 连接层加长度头，避免把二进制帧存进 `offlinemessage` 或登录响应的 JSON 数组。
- **消息上限 4MB**：超限直接断开，防止恶意长度头导致内存膨胀。
- **连接池大小 8、配置硬编码**：沿用原 `db.cpp` 的默认值，不新增配置文件/环境变量。
- **SQL 采用转义而非预处理语句**：改动面小且能消除注入与引号问题；预处理语句重构不在本次范围。
- **`MySQL::connect()` 保留**：语义变为“池连接是否可用”，避免 Model 层调用点大改。
- **不改数据库表结构**，不改业务语义（登录/私聊/群聊三路转发、离线消息逻辑保持原样）。
